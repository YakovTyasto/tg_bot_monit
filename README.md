# Telegram BTC Position Monitor

Персональный Telegram-бот для мониторинга позиции Bitcoin. Он не подключается к бирже,
не торгует и не хранит API-ключи биржи: только собирает публичные рыночные данные,
считает состояние позиции и отправляет анализ.

Параметры позиции зафиксированы в коде:

- цена входа: **$79,234**;
- первоначальная стоимость: **$50,000**;
- количество: `50000 / 79234` = **0.63104223 BTC**;
- комиссии пока не учитываются;
- время отчёта: **08:00, Indian/Mauritius (UTC+4)**.

## Что делает бот

- ежедневно отправляет русскоязычный отчёт с текущей стоимостью и P&L;
- оценивает кратко- и среднесрочную структуру, SMA, волатильность, недавние
  high/low и приблизительные зоны support/resistance;
- показывает DXY/индекс доллара, доходность US Treasury 10Y, текущий диапазон ставки
  ФРС и ближайшие важные релизы BLS, когда данные доступны;
- отбирает за 24 часа только значимые Bitcoin/ETF/ФРС/инфляционные/регуляторные
  новости, классифицирует их и объясняет влияние;
- формирует сценарии BASE/BULL/BEAR на 24 часа, 2–3 дня, 7 дней и 1–3 месяца без
  выдуманных вероятностей;
- сравнивает текущую картину с предыдущим ежедневным отчётом;
- проверяет рынок примерно раз в час, но пишет только при значимом движении,
  пробое зоны, существенном изменении P&L/оценки или действительно важной новости;
- хранит антиспам-state в `state/state.json`. State коммитится Actions только после
  отправленного отчёта или алерта, а не при каждом часовом запуске.

Рыночные данные имеют резервирование между CoinGecko, Kraken и Coinbase. Макро-данные
берутся из FRED/Yahoo Finance и официального календаря U.S. Bureau of Labor Statistics.
Новости обнаруживаются через прямые RSS-ленты и Google News RSS с фильтром источников.
Если отдельный источник недоступен, бот продолжает работу с резервным источником и
помечает ограничение в отчёте. Стабильного бесплатного keyless API для точных ETF flows
и live-вероятностей ставки ФРС нет, поэтому бот включает такие данные только тогда,
когда за последние 24 часа найдено надежное сообщение, и ничего не выдумывает.

## 1. Создать Telegram-бота и получить токен

1. В Telegram откройте официальный аккаунт **@BotFather**.
2. Отправьте `/newbot`.
3. Задайте отображаемое имя и username, который заканчивается на `bot`.
4. BotFather пришлёт токен. Это значение для `TELEGRAM_BOT_TOKEN`.
5. Не отправляйте токен другим людям, не вставляйте его в код и не коммитьте в Git.

Если токен когда-либо попал в публичное место, отзовите его через BotFather и создайте
новый.

## 2. Получить `TELEGRAM_CHAT_ID`

1. Откройте созданного бота и нажмите **Start** или отправьте ему `/start`.
2. На своём компьютере временно задайте токен в переменной окружения:

   ```bash
   export TELEGRAM_BOT_TOKEN='токен_от_BotFather'
   ```

3. Выполните:

   ```bash
   curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getUpdates"
   ```

4. Найдите `result` → `message` → `chat` → `id`. Это числовое значение для
   `TELEGRAM_CHAT_ID`.

Если `result` пуст, ещё раз отправьте боту `/start` и повторите запрос. Команда выше не
сохраняет сам токен в истории shell — в истории остаётся только имя переменной.

## 3. Добавить GitHub Actions secrets

В репозитории GitHub откройте:

**Settings → Secrets and variables → Actions → New repository secret**

Создайте два repository secrets, названия должны совпадать точно:

| Secret | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_CHAT_ID` | числовой chat id |

Секреты не нужно и нельзя добавлять в `.env.example` или любой отслеживаемый Git-файл.
Workflows уже запрашивают `contents: write`, чтобы сохранять state. Для обычного личного
репозитория дополнительных настроек не требуется. Если в репозитории вручную включены
жёсткие branch protection rules, разрешите `github-actions[bot]` обновлять
`state/state.json`.

## 4. Отправить первый тестовый отчёт

1. Откройте вкладку **Actions** репозитория.
2. Выберите **Daily BTC report**.
3. Нажмите **Run workflow → Run workflow**.
4. Через несколько минут отчёт должен прийти в Telegram.

Workflow **Hourly BTC alerts** также можно запустить вручную, но это не принудительный
тестовый спам: если значимого события сейчас нет, он корректно завершится без сообщения.

## 5. Локальный запуск

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В локальном `.env` замените значения на настоящие. Файл `.env` игнорируется Git.

Предпросмотр полного отчёта без Telegram и без изменения state:

```bash
python monitor.py daily --dry-run
```

Реальная отправка:

```bash
python monitor.py daily
python monitor.py alerts
```

## Расписание и state

- `.github/workflows/daily-report.yml`: cron `0 4 * * *`, то есть 04:00 UTC = 08:00
  Маврикия. На Маврикии нет сезонного перевода часов.
- `.github/workflows/market-alerts.yml`: cron `17 * * * *`, примерно раз в час.
- GitHub предупреждает, что scheduled workflows иногда стартуют с небольшой задержкой;
  указанное время — целевое.
- Общая concurrency group не позволяет ежедневному и часовому workflow одновременно
  перезаписывать state.
- Сообщения автоматически разбиваются на части до 3900 символов, ниже лимита Telegram
  `sendMessage` в 4096 символов.
- Состояние записывается атомарно и коммитится только после успешной отправки Telegram.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m compileall -q monitor.py btc_monitor tests
ruff check .
pytest
```

CI запускает те же проверки и дополнительно парсит все GitHub Actions YAML-файлы.

## Важное ограничение

Это автоматический информационный мониторинг, не финансовая рекомендация и не торговый
сигнал. Технические уровни и сценарные диапазоны приблизительны; решение нельзя строить
только на одном отчёте или заголовке новости.
